# MTG Rules RAG — Project Context for Claude

## What This Project Does

A Retrieval-Augmented Generation (RAG) system for answering Magic: The Gathering rules questions. The user asks a natural-language question and gets a precise ruling with cited rule numbers.

**Example:**
- Q: "In combat, one creature has first strike and another has deathtouch — who survives?"
- A: The first strike creature survives. First strike (rule 702.7) causes its damage to be dealt in the first combat damage step (rule 510.5). The deathtouch creature receives lethal damage and dies before it gets to deal damage in the regular combat damage step. Rule 702.2b defines deathtouch as requiring any nonzero damage to be lethal, but the creature never deals its damage.

## Architecture

### Retrieval: TF-IDF (sklearn)
- `mtg_rules.txt` is split into **826 chunks**, one per numbered rule group
- A rule group = parent rule + all lettered sub-rules (e.g. 702.7. + 702.7a + 702.7b)
- Pattern used to detect parent rules: `^\d{3,4}\.\d+\.\s` (e.g. `702.7. First Strike`)
- TF-IDF with bigrams (`ngram_range=(1,2)`) + cosine similarity for retrieval
- No model downloads required — fully offline retrieval
- Index is serialised to `mtg_index.pkl` via pickle

### Generation: Claude API
- Model: `claude-sonnet-4-6`
- Top-6 retrieved rule chunks are passed as context
- System prompt instructs Claude to act as a rules judge and cite rule numbers
- Requires `ANTHROPIC_API_KEY` environment variable

### Why TF-IDF instead of dense embeddings?
- The environment is behind a proxy that blocks HuggingFace model downloads
- TF-IDF works very well for rules lookup (keyword + phrase matching on structured text)
- No API key or internet connection needed for the retrieval step

## Key Constants (mtg_rag.py)

| Constant | Value | Purpose |
|----------|-------|---------|
| `RULES_FILE` | `mtg_rules.txt` | Input text file |
| `INDEX_FILE` | `mtg_index.pkl` | Serialised TF-IDF index |
| `CLAUDE_MODEL` | `claude-sonnet-4-6` | LLM for answering |
| `TOP_K` | `6` | Number of rule chunks retrieved per query |
| `MIN_CHUNK_CHARS` | `80` | Minimum chunk size (filters TOC stubs) |

## CLI Usage

```bash
# First-time setup (builds mtg_index.pkl from mtg_rules.txt)
python mtg_rag.py setup

# Set API key (required for query/interactive mode)
export ANTHROPIC_API_KEY="sk-ant-..."

# Single question
python mtg_rag.py query "can a creature block if it has summoning sickness?"

# Interactive REPL
python mtg_rag.py
```

## Regenerating mtg_rules.txt

If you need to re-extract from the PDF (e.g. after a rules update):

```python
import fitz  # pymupdf

doc = fitz.open("MagicCompRules.pdf")
all_text = "\n".join(page.get_text() for page in doc)

# Rules body starts at position ~4596, glossary at ~546748
rules_text = all_text[4596:546748]
gloss_text = all_text[546748:]

# Then clean and write — see the extraction logic from the original session
```

The positions `4596` and `546748` are for the current PDF version (effective November 1, 2013).
After updating, re-run `python mtg_rag.py setup` to rebuild the index.

## Environment Constraints

- **Proxy blocks HuggingFace** — do not attempt to use `sentence-transformers` or any
  library that downloads models from `huggingface.co` at runtime
- **`cryptography` package has a broken `_cffi_backend`** — avoid libraries that depend
  on it (e.g. `pdfminer.six`, the `pypdf` crypt provider). Use `pymupdf` (`fitz`) for PDF work
- Python 3.11, Linux
- `sklearn`, `numpy`, `anthropic`, `pymupdf`, `chromadb` are all installed

## MTG Rules Structure Reference

The Comprehensive Rules use a strict numbering system:

```
1. Game Concepts          ← top-level section (in TOC only)
  100. General            ← major section header
    100.1. Rule text...   ← parent rule (our chunk boundary)
      100.1a Sub-rule...  ← sub-rule (stays in parent chunk)
      100.1b Sub-rule...
  101. The Magic Golden Rules
    101.1. ...
...
7. Additional Rules
  700. General
  701. Keyword Actions
  702. Keyword Abilities   ← keywords are in the 700s
    702.2. Deathtouch
    702.7. First Strike
    702.4. Double Strike
...
Glossary                  ← starts at char ~546748 in extracted text
```

Commonly referenced rules for combat questions:
- `506` — Combat Phase steps
- `510` — Combat Damage Step (first strike interaction: `510.5`)
- `702.2` — Deathtouch
- `702.4` — Double Strike
- `702.7` — First Strike
- `702.17` — Trample
- `702.18` — Vigilance
- `702.19` — Reach
